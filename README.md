# Keepsake — лендінг на Pug, SCSS та Vite

Навчальний проєкт для лабораторної роботи №9 з дисципліни «Web-технології». Мета — зібрати лендінг Keepsake за допомогою Pug і модульного SCSS, налаштувати обробку стилів у Vite та підготувати сторінку до публікації на GitHub Pages.

**Репозиторій:** https://github.com/Bohdan7563/landing-keepsake-vite  
**Демо:** https://bohdan7563.github.io/landing-keepsake-vite/ *(з'явиться після успішного налаштування GitHub Pages)*

## Використання навчального прикладу

Під час підготовки проєкту як орієнтир для структури та окремих технічних рішень використовувався публічний навчальний приклад [UdalovIvanw/landing-keepsake-vite](https://github.com/UdalovIvanw/landing-keepsake-vite). Його автор повідомлений про використання як прикладу та підтримує такий формат навчального використання. Перед здачею реалізацію потрібно перевірити, зрозуміти й узгодити з власною роботою Keepsake з лабораторної №7.

## Технології та інструменти

| Інструмент | Для чого використовується |
| --- | --- |
| Vite | Локальний сервер розробки та production-збірка |
| Pug | Шаблони сторінки, повторно використовувані фрагменти й цикли для даних |
| Vituum та Pug plugin | Підключення Pug до процесу збірки Vite |
| Dart Sass | Компіляція SCSS |
| PostCSS та Autoprefixer | Додавання CSS-префіксів відповідно до Browserslist |
| sharp | Підготовка AVIF, WebP і JPEG різних розмірів |
| Prettier та @prettier/plugin-pug | Форматування файлів проєкту, включно з Pug |
| Stylelint | Перевірка SCSS і правил іменування класів |
| Husky та lint-staged | Автоматичні перевірки змінених файлів перед комітом |
| GitHub Actions | Автоматична збірка й публікація на GitHub Pages |

## Вимоги до середовища

- Node.js — версія 20.19+ або сумісна актуальна LTS-версія.
- npm — версія, що постачається з установленою версією Node.js.
- Git для роботи з репозиторієм.

## Запуск і команди

Після клонування репозиторію виконайте:

```bash
npm ci
npm run dev
```

Основні команди:

| Команда | Призначення |
| --- | --- |
| `npm run dev` | Запуск локального сервера розробки |
| `npm run build` | Production-збірка в папку `dist/` |
| `npm run preview` | Перегляд production-збірки локально |
| `npm run format` | Форматування файлів через Prettier |
| `npm run lint` | Перевірка SCSS і форматування |
| `npm run lint:styles` | Перевірка SCSS через Stylelint |
| `npm run lint:format` | Перевірка форматування без змін |
| `npm run images` | Генерація зображень із вихідних файлів у `raw-images/` |

> Скрипт `npm run images` потребує вихідних растрових файлів у папці `raw-images/`. У репозиторії зберігаються вже підготовлені варіанти зображень у `src/assets/images/`. Якщо вихідні файли не додані, повторна генерація не виконується.

## Структура

```text
.
├── .github/workflows/       # workflow для GitHub Pages
├── .husky/                  # Git hooks
├── scripts/                 # допоміжні скрипти
├── src/
│   ├── assets/images/       # AVIF, WebP і JPEG у двох ширинах
│   ├── components/          # шапка, підвал і секції сторінки
│   ├── data/                # дані для повторюваних елементів
│   ├── includes/             # SVG-спрайт та інші фрагменти
│   ├── layouts/              # базовий Pug-макет
│   ├── mixins/               # повторно використовувані Pug-міксини
│   ├── pages/                # сторінки
│   └── styles/
│       ├── abstracts/        # змінні, функції, міксини, брейкпоінти
│       ├── base/             # базові стилі та CSS custom properties
│       ├── components/       # стилі компонентів
│       ├── layout/           # стилі структури сторінки
│       └── main.scss         # головна точка входу SCSS
├── postcss.config.js
├── vite.config.js
├── package.json
└── package-lock.json
```

## Як організовано розмітку

Базовий документ описаний у `src/layouts/main.pug`. Сторінка `src/pages/index.pug` успадковує цей макет, підставляє метадані й додає секції. Шапка, підвал і секції винесені в окремі Pug-файли. Повторюваний вміст зберігається в масивах об'єктів у `src/data/` та виводиться циклом `each`. Для кнопок, іконок, адаптивних зображень і карток робіт використовуються Pug-міксини.

## Як організовано стилі

Файл `src/styles/main.scss` є єдиною точкою входу. Стилі поділені на модулі: базові правила, абстракції, компоненти та компонування сторінки. Для підключення модулів застосовуються `@use` і `@forward`; застарілий `@import` не використовується. Класи компонентів організовані за БЕМ, а адаптивні правила згруповані через SCSS-міксин брейкпоінтів.

## Цільові браузери

Список браузерів визначено у `.browserslistrc`:

```text
last 2 Chrome versions
last 2 Firefox versions
last 2 Edge versions
last 2 Safari versions
last 2 iOS versions
```

Autoprefixer використовує цей перелік під час обробки CSS. Мініфікацію production CSS виконує збирач Vite.

## Підготовлені зображення

У `src/assets/images/` наявні AVIF, WebP і JPEG для двох зображень (`work-01` та `journal-01`) у ширинах 400 і 800 пікселів. Фактичний розмір наявних файлів:

| Набір | AVIF 400/800 | WebP 400/800 | JPEG 400/800 |
| --- | ---: | ---: | ---: |
| journal-01 | 0.66 / 1.18 KB | 0.93 / 2.53 KB | 2.43 / 5.54 KB |
| work-01 | 4.46 / 9.54 KB | 4.93 / 10.31 KB | 7.51 / 17.36 KB |

Це розміри файлів, що зараз містяться в папці зображень; порівняння «до/після» можна наводити лише після вимірювання вихідних оригіналів.

## Публікація

Workflow у `.github/workflows/deploy.yml` запускається після push у гілку `main`, встановлює залежності, виконує `npm run build` і публікує папку `dist/` через GitHub Pages. У `vite.config.js` базовий шлях для production налаштований для репозиторію `/landing-keepsake-vite/`.

У налаштуваннях GitHub репозиторію в розділі **Settings → Pages** джерелом публікації має бути **GitHub Actions**.

## Перевірка перед здачею

На чистому клоні потрібно виконати:

```bash
npm ci
npm run lint
npm run build
npm run preview
```

Також потрібно перевірити згенерований HTML у W3C Validator, переглянути адаптивність сторінки, завантаження зображень у DevTools та успішний запуск workflow GitHub Pages. Ці перевірки слід вважати завершеними лише після фактичного виконання команд і перегляду результатів.
